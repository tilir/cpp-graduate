# LRU на C

Сборка и запуск (компилятор C11 и make):

```sh
make
echo '2 6 1 2 1 2 1 2' | ./lru
# 4
make test
```

На stdin подаются неотрицательная вместимость кеша, количество запросов
и указанное количество целых чисел. Числа — знаковые 64-битные,
разделитель — любой пробельный символ. На stdout выводится только число
попаданий и перевод строки. Ошибки ввода и выделения памяти выводятся
в stderr с ненулевым кодом завершения. Данные после указанного количества
запросов не обрабатываются. При нулевой вместимости все запросы — промахи.

## Компоненты

- `include/list.h`, `src/list.c`: непрозрачные `List` и `ListNode`.
  Создание и удаление узлов, доступ к значениям, получение первого/последнего
  узла и перемещение в начало выполняются только через функции компонента.
  Список владеет узлами, клиент — значениями. Операции с узлами — O(1).
- `include/hash_map.h`, `src/hash_map.c`: непрозрачная таблица `HashMap`.
  Поиск возвращает значение через выходной параметр; внутренние записи вообще
  не входят в интерфейс. Таблица владеет записями и корзинами, клиент — значениями.
  Поиск, вставка и удаление по ключу — в среднем O(1), в худшем случае O(n).
- `include/lru.h`, `src/lru.c`: кеш с типами `PageId` (ключ), `Page`
  (значение страницы), `SlowGetPage` (указатель на функцию загрузки).
- `src/main.c`: потоковый ввод, учебный загрузчик и подсчёт попаданий.

## Передача загрузчика

```c
static Page slow_get_page(PageId key) {
    return key;
}

LruCache *cache = lru_create(capacity);
if (!cache) {
    /* обработать ошибку создания */
    return;
}
Page page;
LruResult result = lookup_update(cache, next_page, &slow_get_page, &page);
if (result == LRU_HIT || result == LRU_MISS) {
    process_page(page);
}
lru_destroy(cache);
```

Указатель на загрузчик передаётся в каждый вызов `lookup_update` и вызывается
только при промахе. Кеш его не сохраняет: для следующего запроса можно передать
другую функцию. Смена загрузчика не сбрасывает уже сохранённые страницы;
при попадании возвращается прежнее значение. Реальная функция могла бы получать страницу с диска или из сети;
в учебном примере она просто возвращает ключ. `Page` и `PageId` определены
как `int64_t`, страница хранится по значению внутри записи: отдельные `malloc`
и callback освобождения страницы не нужны. Для другого представления страницы
нужно изменить тип `Page` и определить соответствующий контракт владения.
Текущий простой контракт загрузчика предполагает успешное получение страницы
для каждого ключа; для источника с ошибками потребуется расширить его результат.

При попадании `lookup_update` переносит запись в начало списка и возвращает сохранённую
страницу. При промахе создаёт запись и узел в начале списка, добавляет узел
в индекс, вызывает `slow_get_page` и вытесняет последнюю страницу при заполнении
кеша. Все операции, способные завершиться ошибкой выделения памяти, выполняются
до вызова загрузчика; при ошибке временная запись удаляется. Создание записи, изменение давности, публикация и вытеснение
выделены в отдельные внутренние операции. При ошибке выделения памяти или
вставки в индекс содержимое и порядок кеша сохраняются.

`LruResult` различает попадание, промах, нехватку памяти, неверные аргументы
и ошибку индекса. Ошибки оставляют выходное значение неизменным.
Нулевая вместимость означает вызов загрузчика на каждом запросе без хранения.
Ноль и отрицательные числа являются полноценными значениями страниц.
Обратный вызов не должен повторно входить в тот же кеш.

Память выделяется для служебных записей при промахах и для массива корзин
при создании. Временно при замене существует одна дополнительная запись.
Обработка запроса занимает в среднем O(1) без учёта загрузчика, худший случай
при коллизиях — O(вместимость). Память программы —
O(min(вместимость, число запросов)). В рабочем коде нет `assert`.

`make test` проверяет компоненты, коллизии, вытеснение, давность, крайние числа,
ошибки ввода, длинные последовательности и 300 случайных сравнений с эталоном.
Тесты загрузчика проверяют возврат ключа без выделения страницы, отсутствие
вызовов при попадании и отдельный источник, возвращающий значение, отличное
от ключа. Проверяется также смена загрузчика на одном кеше: сохранение
значения при попадании и использование новой функции после вытеснения. Требуется Python 3 со стандартной библиотекой.

Все определения структур компонентов находятся только в соответствующих `.c`.
LRU хранит в таблице непрозрачные указатели на узлы списка. Для чтения страницы
он вызывает `list_value`, для обновления давности — `list_move_front`.
Прямого доступа к полям списка или таблицы, встраивания их узлов и приведений
указателей с опорой на расположение полей нет. `CacheEntry` — собственные
закрытые данные LRU. Тесты компонентов также используют только публичные API.
